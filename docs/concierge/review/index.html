04

SAFE AUTO-FIX LOOP

  • 1 Confirm: retry from a second region. A blip gets closed and noted in the brief.
  • 2 Classify with the runbook: our code · WordPress/plugin · host · Cloudflare/DNS · gateway.
  • 3 Alert first: you get a P1 message within 2 min with what broke, since when, a screenshot and a first guess. Grace gets "we're on it".
  • 4 Fix only code we own (PEPTICITY pages; WordPress child theme and snippets once they're in git). The fix agent has no production keys. It reproduces the problem, makes the smallest change on fix/<id>, runs checks, and opens a PR with before/after proof.
  • 5 You merge. The checkout journey re-runs, and the incident closes after 2 clean runs.
  • 6 Stop at 30 min or if it isn't our code. You get the full findings: what was checked, what was ruled out, and who to call.
  • Never: push to production, edit live WordPress, change DNS, update plugins live, roll back a database, or retry anything that charges money.
  • Why so strict: Replit (Jul 2025) and PocketOS (Apr 2026). In both, a coding agent deleted a production database.
05

SAFETY

  • Defaults: money and customer messages always wait for a human tap. Replies start as drafts. Production is read-only.
  • Secrets: kept only in the vault. The one token on disk is locked to the agent. Keys rotate every 90 days, one key per job.
  • Kill switch, three ways: text STOP CONCIERGE, press PAUSE ALL in the panel, or revoke the vault token. Nothing restarts by itself. It gets tested in week 1, then monthly.
  • Rate limits: 20 customer emails/hour, 1 per customer per day per type · 3 fix runs/day · US$10/day AI cap · any email sent without an approval trips the kill switch.
  • Resists: emails that try to give it orders (reading has no money or send tools), fake bank emails (sender is verified), runaway loops, bad fixes (it can't merge), and dying silently (a heartbeat alerts you).
